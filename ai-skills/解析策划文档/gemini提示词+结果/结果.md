# PK赢好礼 - 后端逻辑大纲

- **基础系统与资产**
    - **资产定义**
        - **夺宝积分**：本玩法的核心货币，仅在单次PK周期内有效，用于胜负判定。
        - **夺宝卡**：平台级道具，有有效期和单日使用上限，使用后增加夺宝积分。
    - **配置结构**
        - **奖池配置**：ID、周期(小时)、奖励列表(分级：自选/高/中/低/保底)、大奖价值阈值。
        - **任务配置**：任务类型(试玩/高额/视频)、基础积分、基础数量。
        - **系数配置**：ECPM加成系数、决战时刻翻倍系数、唤醒加成系数、机器人K值曲线。

- **PK核心流程**
    - **生命周期管理**
        - **状态机**：`无PK` -> `匹配中` -> `进行中` -> `结算待领取` -> `历史记录`。
        - **周期控制**：
            - **开始**：用户选择奖池发起匹配。
            - **进行中**：记录开始时间，计算剩余时间。
            - **决战时刻**：周期最后24小时（配置决定），触发全局积分翻倍状态。
            - **结束**：倒计时结束 或 用户/机器人触发提前胜利条件。
    - **匹配逻辑**
        - **请求处理**：接收匹配请求，锁定奖池。
        - **数据生成**：随机生成/读取机器人配置（头像、昵称、初始策略组），创建PK会话记录。
    - **放弃机制**
        - **触发**：用户主动放弃。
        - **处理**：标记当前PK会话失效，清空夺宝积分，重置用户状态为`无PK`。

- **任务与积分系统**
    - **每日刷新**
        - **时机**：每日 00:00。
        - **重置内容**：每日任务状态、每日转盘进度、夺宝卡使用次数。
    - **任务生成与调整 (ECPM策略)**
        - **计算 V1 (用户今日价值)**：`Σ(任务价值 * 任务数量 * 用户ECPM)`。
        - **计算 V2 (期望价值)**：`(奖池价值 / 周期) * 1.5`。
        - **动态调整**：
            - **高ECPM (V1 > V2*k)**：任务数量不变，单任务积分翻 `V1/V2` 倍。
            - **低ECPM (V1 < V2)**：任务积分不变，视频任务数量增加 `(V2-V1)/(单任务价值*ECPM)`。
    - **任务完成逻辑**
        - **积分公式**：`最终积分 = ((基础积分 * ECPM系数) + 唤醒额外积分) * 决战时刻系数`。
        - **唤醒机制**：
            - **判定**：若用户 >X 小时未获取积分，标记为唤醒状态。
            - **生效**：回归后前 X 次任务享受额外加分，当日 24:00 失效。
    - **交互事件**
        - **夺宝卡使用**：校验库存、校验日上限 -> 增加积分。
        - **炸弹机制**：触发后扣除对方积分（需处理负分逻辑）。
        - **反超留言**：
            - **触发**：积分变更后，若 `前一刻落后 && 当前领先`，标记“可留言”状态。
            - **执行**：用户发送留言 -> 获得额外积分奖励。
            - **接收**：登录时检测是否有未读机器人留言 -> 触发“收到留言”状态（引导做任务）。

- **机器人系统 (惰性计算模式)**
    - **核心原则**：无定时任务，所有状态变更在**用户请求接口时**（如登录、刷新首页、完成任务）计算。
    - **进度模拟**
        - **输入**：PK开始时间、当前时间、机器人策略组(K值, 时间段方案)。
        - **计算**：
            - 根据时间流逝比例和K值曲线，计算机器人**应有总积分**和**应完成任务数**。
            - 若 `当前模拟值 > 上次记录值`，更新数据库记录。
    - **事件触发判定**
        - **反超判定**：若 `模拟积分 > 用户积分` 且 `上次记录 < 用户积分` -> 写入机器人留言记录。
        - **炸弹判定**：若 `模拟任务数 >= 转盘条件` 且 `今日未触发炸弹` -> 触发炸弹效果（扣用户分）。
        - **提前放弃**：若 `用户价值 > 奖池价值` -> 计算机器人放弃时间点（随机延迟），到达该时间点后判定用户直接胜利。

- **转盘/福袋系统**
    - **资格判定**：监听任务完成事件 -> 累计当日完成数 -> 达到阈值解锁抽奖次数。
    - **抽奖逻辑**
        - **消耗**：消耗当日抽奖次数。
        - **奖励**：根据 ECPM 分层随机（`[0,100)` vs `[100,200)`）。
        - **副作用**：触发“减少对方积分”效果。

- **结算系统**
    - **触发时机**
        - 倒计时归零。
        - 用户总价值 >= 奖池大奖价值（直接胜利）。
        - 机器人投降（被动胜利）。
    - **价值核算**
        - `净价值 = 用户周期总产生价值 - 用户转盘已获价值`。
        - `阈值 = 奖池大奖价值`。
    - **分级发奖**
        - **胜利 (净价值 >= 阈值)**：下发自选奖励权限。
        - **高级 (净价值 >= 80%阈值)**：随机库A抽奖。
        - **中级 (净价值 >= 50%阈值)**：随机库B抽奖。
        - **低级 (净价值 >= 20%阈值)**：随机库C抽奖。
        - **保底 (净价值 < 20%阈值)**：固定奖励。
    - **异常处理**
        - **中断恢复**：结算状态需持久化，若流程中断（如断网），下次登录继续展示结算流程，结果不可变。

- **风控与监控**
    - **产出限制**
        - **每日任务/转盘**：配置单日总产出价值上限 -> 超限后降级为固定小额奖励。
        - **结算奖励**：配置单日大奖库存 -> 库存耗尽提示“明日再来”。
    - **补发机制**
        - 记录所有发奖请求 -> 异步校验到账状态 -> 失败自动重试/补发。
