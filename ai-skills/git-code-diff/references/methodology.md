# 代码参数对比完整方法论

## 一、工作流程概述

```
1. 确定改造边界
   ↓
2. 获取改造前代码
   ↓
3. 分析改造后代码  
   ↓
4. 建立参数对照表
   ↓
5. 逐项验证
   ↓
6. 输出报告
```

## 二、详细步骤

### 步骤1：确定改造边界

**目标**：找到改造的起点和终点

**方法**：
1. 查找所有涉及改造相关函数的提交
2. 确定改造前的代码版本（通常是合并提交）
3. 确定改造涉及的目录和文件范围

**命令示例**：
```bash
# 查找涉及某函数的提交
git log --oneline --all -S "functionName" | head -20

# 查找合并提交
git log --oneline --all --merges | head -20

# 查看特定作者的所有提交
git log --author="author-name" --oneline --name-only | head -50
```

### 步骤2：获取改造前代码

**目标**：获取改造前各业务场景的原始调用方式

**方法**：
1. 找到改造前的代码版本
2. 查看所有调用原函数的业务场景
3. 记录每个场景的参数来源

**关键检查点**：
- 函数的参数来源是什么？
- 是否有特殊处理逻辑？
- 返回值如何被使用？

### 步骤3：分析改造后代码

**目标**：理解改造后的函数签名和内部逻辑

**方法**：
1. 查看改造后函数的签名变化
2. 分析新增参数的作用
3. 理解返回值类型变化

**重点关注**：
- 新增参数的默认值
- 参数校验逻辑
- 错误处理

### 步骤4：建立参数对照表

**目标**：将改造前后的参数一一对应

**模板**：

| 场景 | 改造前函数调用 | 参数1 | 参数2 | 参数3 | 参数4 | 参数5 |
|------|---------------|-------|-------|-------|-------|-------|
| 场景A | func1(openID, tid, riskType, ...) | openID | tid | riskType | - | - |
| 场景B | func2(openID, newTid, ...) | openID | newTid | riskType | - | - |

### 步骤5：逐项验证

**验证清单**：

- 基础参数（openID, tid）是否一致
- 业务参数（riskType, recordType）是否正确映射
- 时间参数（nowT）来源是否一致
- 奖励参数（rewards/pools）结构是否兼容
- 选项参数（options）是否正确传递
- 返回值是否正确处理

### 步骤6：输出报告

**报告结构**：

```
## 📊 改造名称 参数对比报告

### 一、改造概述
- 改造前函数：xxx
- 改造后函数：yyy
- 涉及场景：N个

### 二、参数对比
[逐场景详细对比]

### 三、问题汇总
[发现的问题列表]

### 四、总体评价
[结论]
```

## 三、常见问题处理

### 问题1：找不到改造前的代码

**原因**：代码已被删除或重构

**解决方案**：
1. 查找最早的提交记录
2. 使用 git reflog 找回丢失的代码
3. 查看其他分支的代码

### 问题2：参数类型发生变化

**示例**：
```go
// 改造前
func(oldParam string)

// 改造后
func(newParam int)
```

**处理方法**：
1. 找到参数转换的位置
2. 确认转换逻辑是否正确
3. 检查是否有精度丢失

### 问题3：新增必填参数

**示例**：
```go
// 改造前
func(oldParam1, oldParam2)

// 改造后
func(oldParam1, oldParam2, newRequiredParam)
```

**处理方法**：
1. 确认所有调用处是否都已传入新参数
2. 检查是否有遗漏的调用点
3. 验证默认值的合理性

## 四、验证技巧

### 1. 批量替换检查

```bash
# 查找所有调用改造前函数的地方
grep -rn "oldFunctionName" --include="*.go"

# 查找所有调用改造后函数的地方  
grep -rn "newFunctionName" --include="*.go"
```

### 2. 参数溯源

```bash
# 查看某参数的所有赋值位置
git log -p -S "parameterName" --all | grep -A5 -B5 "parameterName"
```

### 3. 调用链追踪

```
DispatchSendReward (入口)
  ↓
dispatchSendRewardCore (核心逻辑)
  ↓
├── containsExchangeReward (检查兑换奖励)
├── sendVip (发送VIP奖励)
├── sendReward (发送普通奖励)
└── mailSendManualAward (发送邮件奖励)
```

## 五、质量标准

### 必须检查的项目

1. 所有业务场景的参数一致性
2. 参数类型兼容性
3. 新增参数的必填性
4. 返回值处理正确性
5. 错误处理完整性

### 报告完整性标准

1. 包含所有涉及的代码文件
2. 参数对照表完整
3. 问题列表清晰
4. 评估结论明确
