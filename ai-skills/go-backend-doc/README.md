# Go 后端文档生成器 Skill

一个专门用于 Go 语言小游戏后端项目的文档生成 skill，支持 gRPC 和 HTTP 协议。

## 功能特点

- ✅ 自动识别项目结构和技术栈
- ✅ 提取业务逻辑和核心流程
- ✅ 生成 gRPC 和 HTTP API 文档
- ✅ 分析数据库表结构和关系
- ✅ 识别 Redis 缓存设计
- ✅ 生成清晰、结构化的 Markdown 文档

## 使用方法

### 基础用法

1. 上传你的 Go 项目代码（可以是压缩包或文件夹）
2. 告诉 Claude："请帮我生成这个项目的技术文档"

### 进阶用法

**关注特定模块：**
```
请生成项目文档，重点关注用户系统和支付模块
```

**指定输出格式：**
```
生成文档时，把 API 接口单独放到一个文件
```

**补充特定信息：**
```
文档已经不错了，能否补充一下缓存设计的部分？
```

## 生成的文档结构

```
README.md               # 主文档
├── 项目概览
│   ├── 技术栈
│   └── 目录结构
├── 核心业务逻辑
│   ├── 用户系统
│   ├── 游戏逻辑
│   └── 其他模块
├── API 接口文档
│   ├── gRPC 服务
│   └── HTTP 接口
└── 数据存储
    ├── 数据库表结构
    ├── 缓存设计
    └── 数据模型关系

API.md                  # 详细接口文档（可选）
DATABASE.md             # 数据库设计文档（可选）
ARCHITECTURE.md         # 架构设计文档（可选）
```

## 示例

### 输入

上传一个包含以下文件的 Go 项目：
- `main.go`
- `model/user.go`
- `service/user_service.go`
- `handler/user_handler.go`
- `proto/user.proto`

### 输出

Claude 会生成类似这样的文档：

```markdown
# 游戏后端项目 技术文档

## 项目概览

### 技术栈
- **语言**：Go 1.21
- **Web 框架**：Gin v1.9
- **RPC 框架**：gRPC
- **数据库**：MySQL 8.0
- **缓存**：Redis 7.0
- **ORM**：GORM v2

### 目录结构
```
.
├── main.go              # 入口文件
├── config/              # 配置管理
├── model/               # 数据模型
├── service/             # 业务逻辑
├── handler/             # HTTP 处理器
├── proto/               # gRPC 定义
└── middleware/          # 中间件
```

## 核心业务逻辑

### 用户系统

**登录流程**
1. 接收用户名和密码
2. 查询数据库验证用户
3. 检查账户状态（是否被封禁）
4. 生成 JWT token
5. 更新最后登录时间
6. 返回用户信息和 token

**业务规则**
- 用户名：3-20 个字符，仅限字母数字下划线
- 密码：使用 bcrypt 加密，成本因子 10
- 24 小时内登录失败 5 次将锁定账户 1 小时

... (更多内容)
```

## 适用场景

✅ **适合的项目：**
- Go 语言后端项目
- 小游戏服务端
- 微服务架构
- 使用 gRPC 或 HTTP
- 使用 MySQL/PostgreSQL + Redis

⚠️ **不太适合：**
- 前端项目
- 非 Go 语言项目
- 纯配置项目
- 极其复杂的大型系统（文件超过 200 个）

## 质量保证

生成的文档会：

1. **准确性**：从源码直接提取，不编造信息
2. **完整性**：覆盖主要模块和接口
3. **可读性**：使用表格、代码块等格式
4. **可维护性**：包含代码位置引用

## 测试用例

项目包含 5 个测试用例（evals），覆盖：
- ✅ 简单的用户服务项目
- ✅ 包含 gRPC 的游戏服务
- ✅ 缺少 proto 源文件的情况
- ✅ 包含 Redis 缓存的项目
- ✅ 大型项目的处理

## 局限性

1. **需要代码访问**：无法仅根据描述生成文档
2. **推断准确度**：缺少明确定义时会进行推断
3. **超大项目**：文件数超过 200 个时建议分模块处理
4. **特殊框架**：对非主流框架的支持可能有限

## 改进建议

如果生成的文档不够理想，可以：

1. 提供更多上下文："这个项目主要做 XXX"
2. 指定关注点："重点说明支付相关的逻辑"
3. 提供示例："参考这个格式来写"
4. 分步骤："先分析结构，再深入细节"
